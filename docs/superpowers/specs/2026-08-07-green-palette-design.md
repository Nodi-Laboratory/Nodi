작성 2026-08-07 · 상태: **설계 확정, 구현 대기**
디자이너 정본: 밝은 `#cadd73` · **중간 `#9ec92e`** · 캔버스 `#fcfcfc`
(2026-08-07 사용자 전달 — 첫 안은 어두운 올리브라 칙칙하다는 지적을 받았다)

---

## 0. 한 줄 요약

브랜드를 오커/노랑 계열에서 **연두-초록 계열**로 옮긴다. 앱 셸과 학습 캔버스는
CSS 변수 두 블록만 고치면 끝나고, **캔버스 그리기 코드 3곳과 관리자 콘솔은
따로 손대야 한다**(토큰을 안 쓴다).

---

## 1. `#cadd73`이 할 수 있는 일과 없는 일

이 색은 밝다 — 상대휘도 0.655. **흰 글자를 얹으면 대비 1.49로 못 읽는다.**
버튼 색이 될 수 없다.

다행히 현재 팔레트에 성질이 같은 자리가 이미 있다. `--accent`(#ffd75e 골든
옐로)이고, `globals.css:51-59` 주석이 그 자리의 규칙을 못 박아 뒀다:

> `--accent`는 **작은 면에서 브랜드가 보여야 하는 곳**에 쓴다 (로고 배지·사이드바
> 활성 칩·태그 칩). ⚠️ **큰 면(카드 배경 등)에 쓰지 말 것** — 원래 팔레트가
> 유치했던 1번 원인이 정확히 그것이다.

`#cadd73`을 그 자리에 그대로 넣는다. **그 규칙도 그대로 상속된다** — 넓은 면에
깔면 D128이 진단한 실패("학습지처럼 보인다")가 색만 바꿔 되돌아온다.

버튼·포커스 링을 맡을 **진한 초록**(`--accent-deep`)을 새로 둔다.

---

## 2. 이 전환이 **고치는** 결함 하나

현재 캔버스의 의미쌍은 오커(AI) ↔ 딥틸(학생)이고, `globals.css:31-33`이 스스로
적어 뒀듯 **상호대비 2.44로 WCAG 비텍스트 기준 3.0에 미달**한다. 그래서 괘선
굵기(AI 2px / 학생 3px)라는 두 번째 신호를 겹쳐 두고 있다.

브랜드가 초록으로 가면 학생 색을 따뜻한 계열로 옮길 수 있고, 여기서 **명도까지
벌리면** 색만으로 처음 기준을 넘는다.

| | AI/종이 | 학생/종이 | 상호 |
|---|---|---|---|
| 현행 (오커 `#bd7a0b` / 딥틸 `#14554f`) | 3.44 | 8.38 | **2.44 ✗** |
| 확정 (초록 `#789e18` / 밤색 `#4a2a12`) | 3.05 | 12.55 | **4.11 ✓** |

**굵기 신호는 그대로 둔다.** 색이 기준을 넘었다고 두 번째 신호를 걷어내면
축소했을 때 다시 약해진다(D128이 굵기를 넣은 원래 이유는 "축소 시 색이 약하다"
였고, 그건 초록이어도 같다).

### 왜 학생 색이 그렇게 진한가 — 피할 수 없는 기하

흰 종이 위에서 두 색이 **각각** 3.0을 넘으면서 **서로도** 3.0을 넘으려면,
한쪽이 반드시 아주 진해야 한다. 계산으로 확인했다 — AI 초록이 종이 대비
3.65(휘도 ≈0.23)면 상대는 휘도 0.043 이하여야 하고, 그건 짙은 밤색 영역이다.
밝은 흙색으로 하면 상호대비가 다시 무너진다(실측: 중간 호박 `#c07a3e` → 2.78).

이 제약은 종이가 밝아질수록 세진다. 캔버스가 `#fbf8f1`에서 `#fcfcfc`로
**더 밝아지므로** 타협 여지는 오히려 줄었다.

## 4. 한 가지 부작용과 그 처방

캔버스가 **따뜻한 종이 → 중성 흰색**으로 바뀐다. 그러면 현재의 따뜻한 먹
(`#221e17`)이 그 위에서 누렇게 떠 보인다 — `globals.css:76`이 **정확히 반대
이유**로 그 값을 골랐기 때문이다("냉회색은 따뜻한 종이 위에서 탁해 보인다").

그래서 잉크를 아주 옅은 초록빛 검정(`#1e2418`)으로 옮긴다. 종이가 밝아진
만큼 괘선도 한 단계 진해야 같은 존재감이 난다(`#e4dac3` → `#d5dfc0`).

## 5. 변경 대상

### 5.1 토큰만 고치면 따라오는 것 (파일 2곳)

- `frontend/src/app/globals.css` `:root` (41~79행) — §3.1
- `frontend/src/app/globals.css` `.canvas2` (238~282행) — §3.2

Excalidraw는 손댈 필요가 없다. 캔버스가 `viewBackgroundColor: "transparent"`
(`ExcalidrawLayer.tsx:154`)이고 `.canvas2 .excalidraw`도 `background: transparent`
(`globals.css:359`)라, **종이색은 `--c-paper` 하나가 결정한다.**

### 5.2 토큰을 안 써서 **따로 고쳐야** 하는 것

canvas 2D의 `ctx`는 CSS 변수를 못 읽는다. `ConceptMap`은 `getComputedStyle`로
읽어 오는 길을 이미 갖고 있는데(`196-198행`이 `--fg`·`--fg-muted`·`--bg-elevated`
를 읽는다) **선 색만 빠졌다.**

| 위치 | 지금 | 해야 할 일 |
|---|---|---|
| `components/home/ConceptMap.tsx:265` | `rgba(160,101,3, …)` (오커 고정) | 같은 `tone()`으로 `--c-live`를 읽어 알파만 계산 |
| `components/home/ConceptMap.tsx:284` | `hsl(40 6% 62%)` (무태그 회색) | `--fg-muted` 계열로 |
| `components/canvas2/Minimap.tsx:86~91` | 태그색 6개 배열 | 초록 브랜드와 어울리는 6색으로 |

⚠️ **이 셋은 화면에 오류가 안 난다.** 토큰을 아무리 고쳐도 조용히 오커로 남고,
지도를 실제로 열어 봐야만 드러난다.

`ConceptMap.tsx:283`의 `hsl(${hue} 62% 52%)`는 **태그 이름 해시**라 브랜드색과
무관하다 — 그대로 둔다(태그마다 다른 색이어야 무리가 갈린다).

### 5.3 별도 결정이 필요한 것

- **관리자 콘솔** — `components/admin/ui.tsx:14`의 `C` 객체(다크 톤 14색) +
  각 탭의 인라인 hex **400개 이상, 16개 파일**. 토큰을 전혀 안 쓴다. 주석이
  "일반 화면과 분명히 구분되게 유지한다"라고 의도를 밝히므로 **그대로 두는 것도
  선택지**다. 초록 계열 다크로 옮기려면 `C` 객체 하나를 고치는 것이 출발점이고,
  탭별 인라인 hex는 그다음 문제다.
- **마스코트** — `frontend/public/nodi-mascot.png`. 래스터라 CSS로 못 바꾼다.

### 5.4 **건드리면 안 되는 것**

- `lib/canvas2/inkRender.ts` — VLM에 보내는 도식이다. **"흰 종이에 검은 획"이
  모델 입력 조건**이라 브랜드가 바뀌어도 그대로 둔다. 여기에 초록을 넣으면
  손글씨 인식 품질이 **조용히** 나빠진다.
- `components/canvas2/ToolRail.tsx` — 학생이 고르는 펜 색 팔레트(Excalidraw
  기본 12색). 브랜드색이 아니다.

### 5.5 함께 정리하면 좋은 것 — 죽은 블록

`globals.css:561~576`의 `.nodi-canvas` 블록은 **캔버스 v1 테마 잔재**다.
그 클래스를 붙이는 컴포넌트가 **하나도 없다**(전수 확인). 여기 든 12개 토큰
(`--yellow` `--orange` `--blue` `--ink` `--text` `--text-dim` `--text-faint`
`--border` `--hl-yellow` `--hl-blue` `--logo-dot` `--shadow*`)이 전부 죽은
값이다. 남겨 두면 전환 작업 중에 "이것도 바꿔야 하나"로 시간을 쓰고, 더 나쁘게는
**바꿨는데 화면이 안 변해서 캐시를 의심하게 된다.**

## 6. 검증

1. `cd frontend && npx tsc --noEmit && npm test -- --run && npx eslint src e2e`
2. **`rm -rf .next` 후 dev 재시작** — `globals.css`는 이것 없이는 다시 컴파일되지
   않는다(2026-08-04 실측, Next 16.2.9 + Turbopack). 화면에 "안 고쳐진 것"으로
   보여서 코드를 의심하며 시간을 버리게 되는 함정이다.
   확인법: `curl -sL localhost:3000/login | grep -o '/_next/static/[^"]*\.css'`
   → 그 주소를 `curl`해서 새 값을 찾는다. 없으면 캐시다.
3. **눈으로 볼 화면 넷** — 색은 테스트가 못 잡는다:
   - `/home` 개념 지도 (§5.2의 선 색이 실제로 바뀌었는지)
   - `/space/personal` 캔버스 (AI 괘선 ↔ 학생 메모 괘선이 갈리는지)
   - 캔버스 미니맵 (축소 상태에서 태그 점)
   - 로그인 화면 (브랜드 배지)
4. 대비 재확인이 필요하면 계산으로 한다 — 이 문서 §3.3의 수치는 WCAG 상대휘도
   공식으로 실측한 값이다.
