# 교차 세션 개념 연결 (D171)

사용자 지시 2026-08-04. **목적은 융합이다** — 학생이 어제 생명과학에서 한
이야기와 오늘 지구과학에서 하는 이야기가 이어져 있을 때, 그 연결을 보여 준다.

옛 Nodi(`Zanviq/Nodi`)의 네비게이터 노드와는 **다른 기능이다.** 저쪽은 다음
질문을 추천했다. 이건 **학생이 볼 수 없는 것**(2주 전의 자기 자신)을 꺼내 온다.

## 왜 지금 다시 만드나

`기억 연결(memory_link)`은 D107에서 제거됐다. 이유는 아이디어가 나빠서가 아니라
**"캔버스 UI에 그 둘을 만드는 경로가 없어 언제나 빈 결과였다"**였다. 이번에
만드는 것이 정확히 그 빠져 있던 입구다. 입구 없이 검색만 되살리면 D107이 그대로
반복된다.

## 없던 인프라 — 이게 본체다

**학생의 대화 내역을 담은 벡터 색인이 없다.** 지금 Qdrant에는 `file_chunks` ·
`chunk_atoms` · `textbook_figures` · `lecture_clips` · `lecture_clip_atoms`
다섯뿐이고, 카드용이던 `canvas_cards`는 D105로 지웠다.

이 기능의 대부분은 UI가 아니라 **개념 카드 색인 파이프라인**을 새로 놓는 일이다.

## 거리는 상한이 아니라 **띠**다

상한 하나만 두면 목적과 어긋난다. **너무 가까운 히트는 버려야 한다** — 그건
융합이 아니라 중복이다("어제도 광합성, 오늘도 광합성").

    crosslink_min_distance (0.45)  ≤  d  ≤  crosslink_max_distance (0.72)

바닥 아래는 같은 얘기, 천장 위는 남남.

### 숫자는 눈대중이 아니라 실측이다

처음에는 0.20~0.38로 잡았다. **재 보니 틀렸다** — 그 띠는 중복만 걸리고 정작
융합은 전부 놓친다. 그대로 냈으면 기능이 한 번도 안 떴을 것이고, "왜 안 뜨지"는
게이트가 까다로워서라고 착각하기 딱 좋았다.

한국어 개념 카드로 `embedding-query`/`embedding-passage` 쌍을 재서 나온 분포
(2026-08-04, 광합성 카드를 축으로):

| 종류 | 거리 |
|---|---|
| 중복 — 같은 주제를 말만 바꿔 씀 | 0.347 |
| **융합 — 다른 과목인데 축을 공유** | **0.567 ~ 0.686** |
| 남남 — 조선 통치 체제 · 이차방정식 | 0.880 ~ 0.904 |

바닥은 중복(0.347)과 융합 하한(0.567) 사이, 천장은 융합 상한(0.686)과
남남 하한(0.880) 사이에 둔다. 양쪽 다 여유가 있다.

표본이 여섯 쌍·축 하나뿐이므로 **1차 캘리브레이션**이다. 실제 학생 데이터가
쌓이면 다시 재야 한다 — 그래서 둘 다 튜너블이다(D62).

## 필터

| 조건 | 이유 |
|---|---|
| `owner_id` = 본인 | 남의 대화는 절대 안 된다 |
| `session_id` ≠ 현재 | 같은 세션 안은 이미 트리가 잇는다 |
| `tag_norm` ≠ 현재 | 사용자 지시 — 같은 태그는 다른 세션이라도 제외 |
| 방향 규칙 (아래) | 사용자 지시 |
| 거리 띠 | 위 |

**태그 비교는 정규화해서 한다.** 태그는 세션마다 모델이 자유롭게 짓는다(D89).
`"생명과학"`과 `"생명 과학"`은 다른 문자열이라 그냥 비교하면 **표기만 다른 같은
주제가 필터를 통과한다** — "다른 과목과 연결됐다"며 같은 과목을 보여 주게 된다.
공백 제거 + 소문자화로 이 구멍을 닫는다.

### 방향 규칙 (사용자 결정 2026-08-04)

**학급 → 개인은 되고, 개인 → 학급은 안 된다.**

- 지금 카드가 **개인** 세션이면: 개인·학급 어디서든 가져올 수 있다
- 지금 카드가 **학급** 세션이면: **학급 세션에서만** 가져온다

개인 공간의 사적인 대화가 학급 맥락으로 새지 않게 하는 규칙이다. 페이로드에
`space_kind`를 넣어 Qdrant 필터로 강제하고, 본문은 어차피 Postgres에서 다시
읽으므로 RLS가 한 번 더 본다.

## Qdrant는 신뢰 경계가 아니다 (불변식)

새 컬렉션 `canvas_concepts`(1024d, Cosine)의 페이로드에는 **식별자만** 넣는다:

    {item_id, session_id, owner_id, tag_norm, space_kind}

본문·제목은 넣지 않는다. 히트 후 `canvas_items` 행을 **사용자 클라이언트로
재조회**해 RLS가 재검증하게 한다(파일 청크와 같은 계약).

## 흐름

1. 턴이 개념 카드를 만들어 저장되면 → `crosslink` 잡 en큐 (비차단)
2. 워커가 그 카드를 `embedding-passage`로 색인
3. 같은 카드를 `embedding-query`로 만들어 교차 검색 (위 필터 + 띠)
4. 통과한 첫 히트 하나에 대해 solar로 **왜·어떻게 관련되는지** 설명 생성
5. `item_links` 행 저장 → 프론트가 배지로 표시

3번에서 대부분 끝난다. 게이트가 까다로워 4번(모델 호출)까지 가는 턴은 드물다.

**임베딩은 비대칭이다**(불변식). 색인은 passage, 검색은 query — 같은 텍스트라도
호출을 나눠야 한다.

**카드 하나에 링크는 최대 1개**(사용자 결정). 여러 개면 배지가 목록이 되고
"드물게"라는 의도가 무너진다. 검색은 `crosslink_top_k`(8)개까지 받아 필터를
통과하는 **첫 하나**만 쓴다.

## 저장

```sql
CREATE TABLE IF NOT EXISTS public.item_links (
    id           uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    owner_id     uuid NOT NULL REFERENCES public.profiles(id) ON DELETE CASCADE,
    from_item_id uuid NOT NULL REFERENCES public.canvas_items(id) ON DELETE CASCADE,
    to_item_id   uuid NOT NULL REFERENCES public.canvas_items(id) ON DELETE CASCADE,
    explanation  text NOT NULL DEFAULT '',
    distance     double precision NOT NULL,
    opened_at    timestamptz,
    created_at   timestamptz NOT NULL DEFAULT now(),
    UNIQUE (from_item_id, to_item_id)
);
```

`UNIQUE (from_item_id, to_item_id)`가 **같은 쌍의 반복 추천을 구조로 막는다.**
`opened_at`은 깜빡임을 멈추는 표식이다 — 한 번 본 알림이 계속 깜빡이면 소음이다.

카드 `data` jsonb에 묻는 방법도 있지만 중복 방지와 양방향 조회가 어렵다.

## 화면

**배지는 아이템이 아니라 카드에 붙는 표식이다.** 카드 오른쪽은 이미 도판·클립이
열로 쌓이는 자리고(D163), 배치 엔진의 무겹침은 알고리즘의 성질이라(D123) 거기에
새 아이템을 끼우면 그 성질이 깨진다. 배지는 카드 오른쪽 **가장자리에 붙는
표식**이라 레이아웃을 건드리지 않는다.

펼친 설명도 같은 이유로 **레이아웃 아이템이 아니라 배지에 앵커된 오버레이**다.
접고 펴는 게 자유로워야 하는데, 아이템이면 펼칠 때마다 주변 카드를 밀어낸다.

깜빡임은 두 가지를 지킨다 — **한 번 열면 멈춘다**, `prefers-reduced-motion`을
존중한다.

## "과거 대화로 돌아가기" — 가장 위험한 부분

버튼 하나로 보이지만 **세션 전환 경로 전체**를 탄다.

- **세션은 공간에 속한다**(D148). 목적지가 학급 세션이면 `activeSessionId`만
  바꾸면 안 되고 `activeSessionSpaceId`까지 함께 옮겨야 한다. 안 그러면 학급
  공간에서 개인 세션이 열리는 그 버그가 재현된다.
- **수화는 세션당 한 번**이다(D147). 세션을 떠날 때 스냅샷을 버리는 그 경로를
  그대로 타야 한다 — 카드 3개가 9개가 됐던 자리다. 새 진입점을 만들면서 이걸
  우회하면 같은 사고가 난다.
- 도착해서 그 카드에 **초점**을 맞춘다(`focusCamera`, 235% 상한 D166).
- **돌아올 길**이 있어야 한다. 어제 세션에 던져 놓고 끝내면 학생은 길을 잃는다.

## 튜너블 (D62)

`crosslink_enabled`(true) · `crosslink_min_distance`(0.20) ·
`crosslink_max_distance`(0.38) · `crosslink_top_k`(8)

`db/03_app_settings.sql`에 기본값을 넣어야 admin 콘솔에 뜬다.

## 학습 효과 관점

앞선 추천 질문과 **반대다.** 저건 학생이 할 일(질문 만들기)을 대신 해 줘서
D138과 부딪혔지만, 이건 학생이 **볼 수 없는 것**을 보여 준다. 영역을 넘는 연결은
전이(transfer)에 가장 가깝고 근거도 탄탄한 쪽이다.

남겨 두는 선택지: 설명을 바로 보여 주는 대신 과거 카드만 먼저 띄우고 "이 둘이
어떻게 연결될까?"를 물은 뒤 펼치면 Active → Constructive로 올라간다. 지금은
사용자 지시대로 바로 보여 주되, 노브 하나로 갈아 끼울 수 있게 열어 둔다.

## 비목표

- 다른 학생의 대화와 연결하지 않는다(본인 것만).
- 같은 세션 안의 연결은 만들지 않는다 — 트리가 이미 잇는다.
- 카드당 링크 2개 이상은 만들지 않는다.
