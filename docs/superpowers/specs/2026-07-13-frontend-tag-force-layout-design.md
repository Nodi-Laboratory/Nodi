# 프론트 d3-force 태그 클러스터 레이아웃 설계

날짜: 2026-07-13
상태: 사용자 승인 완료 (스펙 작성 → 구현 계획 전)
선행: 2026-07-13-tag-based-placement-design.md (서버 태그 배치 — 본 설계가 좌표 계산을 대체)

## 1. 배경과 목표

서버가 태그 앵커(Vogel 나선)로 카드를 고정 배치하지만, 태그 간 거리가 정적이고 태그가 지도에
보이지 않으며 개념트리는 임베딩 그룹으로 점을 찍는다. 요청:

- **태그를 지도에 시각적으로 표시**한다.
- **개념트리(미니맵)는 태그만** 띄운다.
- **태그 클러스터 간 거리는 노드 수에 따라 동적** — 노드가 많을수록 다른 클러스터를 더 멀리 밀어낸다.
  기존 카드도 함께 이동(전체 재배치).

**핵심 결정(승인됨):**
- **전체 재배치**: 새 노드 추가 시 태그 레이아웃 전체 재계산, 기존 카드도 이동.
- **프론트 d3-force**: 프론트가 d3-force로 카드 위치를 계산 — **서버 `place` 좌표를 대체**. 카드
  레이아웃 권위가 프론트로 이동. 위치는 창발적(비영속), 재수화 시 태그+개수로 재시뮬레이션.

## 2. 아키텍처 전환

- **서버**: 태그 배정·영속만 담당 — 스트리밍 `@concept: 제목 | 분류`, `attachments.canvas.concepts[].tag`
  (이미 구현됨). 서버의 `place` 좌표는 **프론트가 무시**한다. 서버 태그 앵커 계산(`tag_anchor`/`place_by_tag`)
  은 사문화 — 물리 제거는 후속(비차단, §9).
- **프론트**: 세션의 개념+태그로 d3-force 시뮬레이션을 돌려 모든 카드 좌표를 정한다. 위치는 영속하지
  않는다(재수화 시 재계산). 결정론 시드로 재수화 레이아웃을 안정화한다.

## 3. `useTagLayout` — d3-force 클러스터 레이아웃 (신규 훅)

### 3-1. 입력·출력
- 입력: 세션 개념 목록 `{ id, tag, h }`. 태그는 라이브(파서 `cluster`)·재수화(attachments `tag`)에서.
  빈 태그 → `"기타"`.
- 출력: `positions: Map<conceptId, {x,y}>` + `tagCentroids: Map<tag, {x,y,count}>`.

### 3-2. 힘 모델 (카드 = force 노드, 태그별 클러스터)
- **클러스터 응집**: 각 카드를 자기 태그의 무게중심으로 당긴다(매 틱 태그 무게중심 재계산 후 `forceX/Y`
  또는 커스텀 cluster force). → 같은 태그가 뭉친다.
- **반발(동적 분리)**: `forceManyBody`(음수 charge). 카드 수가 많은 태그는 **총 반발이 커서** 다른
  클러스터를 더 멀리 밀어낸다 — "노드 많을수록 멀어짐"의 핵심(균일 per-node charge로 자연 달성).
- **무겹침**: `forceCollide` — 카드 반경(≈`hypot(CARD_W, h)/2` 근사)으로 카드끼리 안 겹치게. 캔버스는
  무한 팬이라 패킹 압력 없음(클러스터가 필요한 만큼 퍼짐).
- **경계**: 약한 `forceCenter`(또는 forceX/Y→중앙)로 전체를 중앙 부근에 유지.

### 3-3. 결정론·수렴
- **초기 시드**: 각 카드의 초기 위치 = 그 태그의 첫등장 순서 k를 황금각으로 시드한 지점 + 카드 인덱스
  미소 오프셋. d3의 난수 초기화(x/y 미지정 시)를 피해 **재수화 레이아웃 안정**. (forceCollide의 미세
  jiggle 외 난수 없음.)
- **수렴/애니메이션**: 데이터 변화 시 시뮬레이션 재가열(alpha reset) → 틱마다 위치 갱신(rAF)으로
  **부드럽게 이동**, `alphaMin` 도달 시 정지. 정지 상태에선 CPU 0.

## 4. 지도 태그 시각화 — `TagMarker` (신규)

- 각 태그 무게중심(`tagCentroids`)에 **태그 라벨 마커**를 NoteCanvas 내부에 렌더(팬/줌 따라감).
- 스타일: 칩/라벨 + count 배지. `pointerEvents` 최소, 카드 아래 레이어. count로 크기·강조 가감(선택).

## 5. 개념트리 = 태그만 — `ConceptMinimap` 개편

- `grouping.ts` 임베딩 그룹 대신 **`tagCentroids`** 로 1태그=1점(count로 반경). 뷰포트 사각형 유지.
- 점 클릭 → `onFocus(태그 무게중심)` → 본 캔버스가 그 클러스터로 팬.
- `minimapLayout`(centroid·fit·viewport)은 태그 무게중심 입력으로 재사용. `grouping.ts` 미니맵 의존 제거.

## 6. 기존 기능 적응 (좌표 소스 = useTagLayout)

- **ConceptCard**: `concept.x/y`(서버) 대신 `positions.get(id)`로 렌더 + CSS 트랜지션(부드러운 이동).
- **자동 포커싱**: 새 답변 첫 개념의 sim 위치로 포커스(위치 확정 시).
- **맵 로딩**: 생성 지점(첫 개념 sim 위치 또는 중앙 폴백)에 로딩 버블.
- **단일 리프(영상/삽화)**: sim 위치 기준 앵커 개념 곁 `placeLeafClear`(무겹침) 재사용.
- 서버 `place` 이벤트는 개념 생성 신호로만(좌표는 무시) — 또는 파서 `cstart`로 대체.

## 7. 데이터 흐름

스트리밍/재수화로 개념+태그 확보 → `useTagLayout`(d3-force) → `positions`/`tagCentroids` →
카드·`TagMarker`·`ConceptMinimap` 렌더. 새 개념/태그 → 시뮬 재가열 → 카드가 새 배치로 애니메이션.
서버는 태그를 attachments에 영속(재수화 입력). 좌표는 영속하지 않음.

## 8. 에러 처리

| 상황 | 동작 |
|---|---|
| 태그 0 | 빈 상태(카드·마커·미니맵 없음) |
| 단일 태그 | 중앙 클러스터(반발 대상 없음) |
| 좌표 미확정(첫 틱 전) | 초기 시드 위치 사용(황금각) |
| 시뮬 미수렴(대량) | alphaMin·틱 상한으로 강제 정지 |
| 태그 없는 구 개념 | `"기타"` 태그로 편입 |

## 9. 테스트

### 9-1. 순수 유닛(node 새너티)
- 태그 무게중심 계산(멤버 좌표 평균), 클러스터 반경(count↑→반경↑), 초기 시드(태그 순서 황금각 결정론).
- (d3-force 시뮬 자체는 상태적이라 유닛 대신 E2E로 관찰.)

### 9-2. E2E(Playwright)
1. 같은 태그 질문 다수 → 한 클러스터로 조밀, 태그 마커 1개.
2. 다른 태그 → 분리, **큰 클러스터일수록 이웃과 더 멀다**(멤버 수↑ → 클러스터 중심거리↑).
3. 카드끼리 무겹침(가변 높이).
4. 미니맵이 **태그**를 점으로 표시(1태그=1점), 클릭 → 그 클러스터로 팬.
5. 새로고침 → 태그+개수로 유사 레이아웃 재현(결정론 시드).

## 10. 비범위

- 서버 태그 앵커(`tag_anchor`/`place_by_tag`/place 좌표 emit) **물리 제거**(사문화만; 후속 정리).
- 카드 위치 영속(창발적 레이아웃 — 저장 안 함; attachments의 x/y는 방치/무시).
- 카드 드래그·수동 재배치, 태그 이름 편집/병합.
- 임베딩(EBS/삽화/교과서/파일 검색용) — 배치와 무관, 유지.
- Part B 단일 리프(유지 — 좌표 소스만 sim으로 변경).
