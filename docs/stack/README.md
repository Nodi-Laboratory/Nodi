# 기술 스택

Nodi가 **무엇으로 만들어졌고 왜 그것을 골랐는지**. 문서는 넷으로 나뉜다 —
찾는 것이 다르면 볼 곳도 달라야 한다.

| 문서 | 답하는 질문 |
| --- | --- |
| [`01-overview.md`](01-overview.md) | 전체 그림은? 요청 하나가 어디를 지나가나? |
| [`02-frontend.md`](02-frontend.md) | 화면은 무엇으로 그리나? 캔버스는 어떻게 도나? |
| [`03-backend.md`](03-backend.md) | 서버는 어떻게 짜여 있나? 워커는 무엇을 하나? |
| [`04-data-and-ai.md`](04-data-and-ai.md) | 데이터는 어디에 어떻게 있나? 어떤 모델이 무슨 일을 하나? |

운영·배포는 [`../DEPLOYMENT.md`](../DEPLOYMENT.md), 설계 결정의 **근거**는
저장소 루트 [`../../CLAUDE.md`](../../CLAUDE.md)의 D-번호가 갖는다. 이 문서들은
**무엇을 쓰는지**를 적고, 왜 그렇게 됐는지는 D-번호를 가리킨다.

## 읽는 순서

처음이면 `01-overview.md`만 읽어도 된다. 고칠 곳이 정해졌으면 그 영역 문서로
바로 간다.

## 이 문서들의 규칙

- **버전은 잠금 파일이 정본이다.** 여기 적힌 값은 사람이 읽으라고 옮겨 둔
  것이라 반드시 뒤처진다. 정확한 값은 `frontend/package.json` ·
  `backend/pyproject.toml` · `backend/uv.lock`을 본다.
- **숫자는 실측한 것만 적는다.** "빠르다" 대신 "1,200개에서 16.7ms"라고 쓴다.
  잰 적 없는 값은 아예 안 적는다.
- **없는 것도 적는다.** 안 쓰기로 한 것과 그 이유는 다음 사람이 같은 길을
  다시 파지 않게 한다.

## 틀리지 않았는지 확인하기

```bash
cd backend && uv run python -m scripts.check_docs
```

버전·모듈 수·스킬 이름·튜너블 개수·테스트 수·안 쓰기로 한 의존성·문서 사이
링크를 실제 코드와 대조한다. 문서가 뒤처지는 것은 못 막지만 **처음부터 틀린
것**은 막는다 — 실제로 두 번 잡았다(라우터를 16, 서비스를 40으로 적어 뒀는데
각각 15·36이었다).
