# 사용자 테스트 플로우 100 (2026-08-05)

학생·교사·관리자가 **실제로 밟는 길** 100개. 목적은 목록을 채우는 것이 아니라
**버그를 찾는 것**이라, 각 항목은 "무엇을 하면" / "무엇이 참이어야 하는가"로 쓴다.

실행: `frontend/e2e/flows/*.spec.ts` (그룹별 파일).
로그인 왕복이 비싸므로 그룹당 한 번만 로그인하고 여러 플로우를 이어 태운다.

## 1차 실행 결과 (2026-08-05)

자동화 **45개 / 100개**, 전부 통과(`e2e/flows/` + `ask-ink` + `hydration` +
`canvas` = 56 케이스, 2.2분). 나머지는 교사·관리자 계정이 필요하거나(I81–I88)
사람 눈이 필요한 것들(J92 느린 망, J95 실제 터치)이다.

### 찾아서 고친 버그 둘

**1. 대화 목록의 `⋯` 버튼에 이름이 없었다** (J100 → `SessionList.tsx`)

스크린리더에는 "버튼"으로만 읽히고, `opacity-0`이라 **키보드로 포커스해도
보이지 않았다** — 마우스를 못 쓰는 학생은 대화 이름을 바꾸거나 지울 길이
아예 없었다. 대화 제목을 실은 `aria-label`(목록에 열 개면 열 개가 다 달라야
한다) + `aria-expanded` + `focus-visible:opacity-100`.

**2. "어느 대화를 보고 있나"가 화면에서 관찰 불가능했다** (H71 → `CanvasStage.tsx`)

새 대화를 만든 **직후에 파일을 붙이면 이전 대화로 들어갔다**(실측: 파일의
`session_id`가 앞 세션, 화면은 새 세션을 조회 — 칩이 영영 안 뜬다). 학생은
"업로드가 안 된다"로 겪고 다시 붙인다. 근본 원인은 전환이 끝났는지 **밖에서
알 방법이 없다는 것**이었다: 빈 대화에서 빈 대화로 넘어가면 아이템 수도
입력창 상태도 그대로라 아무 신호가 없다. 캔버스 루트에 `data-session`을
드러내고, 테스트 헬퍼가 그 값이 **실제로 바뀔 때까지** 기다리게 했다.

### 함께 확인된 것 (고치지 않음)

- **확대 ↔ 축소 왕복이 제자리로 안 온다**(100% → 확대 → 축소 = 94%).
  Excalidraw가 배율을 자기 눈금으로 스냅한다. 학생에게 중요한 것은
  "커지고 작아진다"라 방향만 보장하고 뒀다.
- **`e2e/tag.spec.ts`는 없는 기능을 테스트한다** — 태그 **이름 변경** UI가
  코드에 없다(`TagPicker`의 라벨은 분류 선택·추가·취소뿐). 기능을 만들지
  테스트를 걷을지는 제품 판단이라 손대지 않았다.
