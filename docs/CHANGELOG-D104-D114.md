## 0. 배경 — 왜 Supabase를 걷어냈나

로드맵이 **① 협업 리팩토링 → ② Supabase 의존 제거 → ③ UI·기능 업그레이드**였다.
②가 확정돼 있었기 때문에 ①에서 Supabase 인프라(로컬 스택 `config.toml`,
마이그레이션 추적 등)에 투자하지 않고 규칙·문서로만 처리했다.

②를 앞당길 이유가 하나 더 있었다. 마이그레이션 어디에도 API 롤 `GRANT`가 없어서
**Supabase의 구버전 자동 노출 동작에 기대고 있었다.** 신규 기본값에서는 테이블
11개가 전부 `permission denied`였고, RPC도 18개 중 3개만 노출됐다. 그 옵션은
**2026-10-30에 제거될 예정**이라 어차피 손봐야 했다. Supabase를 걷어내면서 이
부채도 함께 사라졌다.

## 1. Supabase 완전 제거 → 순수 Postgres (D104)

가장 큰 변경. **120개 파일 · +3,474 / −7,089줄** — 지운 줄이 넣은 줄의 두 배다.

### 먼저 결합면을 실측했다

추측으로 시작하지 않고 로컬 DB에서 직접 뽑았다:

| 대상 | 수량 |
|---|---|
| RLS 정책 | 32 |
| DB 함수 | 19 (RPC 18 + `handle_new_user` 트리거) |
| `auth.uid()` 참조 | 13개 함수 + **정책 32개 전부** |
| `auth.users` 참조 | **`profiles_id_fkey` 하나뿐** — 함수 본문엔 없음 |

**결정적 발견: Supabase Auth에 대한 DB 결합이 딱 세 군데였다.** `auth.uid()`
함수, `profiles.id → auth.users(id)` 외래키, `auth.users`에 걸린 트리거.

Supabase가 제공하던 것을 넷으로 나눠 각각 대체했다:

| 걷어낸 것 | 대체 |
|---|---|
| Supabase Auth (GoTrue) | 자체 인증 — `public.users` + bcrypt + HS256 JWT |
| PostgREST (HTTP 데이터 API) | asyncpg 직결 + **PostgREST 문법 → SQL 변환기** |
| Supabase Storage | 로컬 파일시스템 (`backend/.storage`, HMAC signed URL) |
| Supabase Realtime | 폴링 (관리자 로그 화면 하나만 쓰고 있었다) |

### 핵심 판단: RLS를 앱 코드로 옮기지 않았다

Supabase Auth가 제공한 것은 **`auth.uid()` 함수 하나뿐**이었다. 그것만 우리
것으로 갈아끼우면 **RLS 정책 32개와 DB 함수 19개가 한 글자도 바뀌지 않고 산다.**

```
요청 → nodi_app 역할로 트랜잭션 시작
     → SET LOCAL app.user_id = '<사용자 uuid>'
     → auth.uid()가 그 값을 돌려주고, 기존 정책들이 그대로 판정
```

`SET LOCAL`은 트랜잭션 스코프라 커밋 시 사라진다 — 커넥션 풀에서 앞 요청의
사용자 컨텍스트가 남는 사고가 **구조적으로** 불가능하다.

> **대안도 검토했다.** 정책·함수 50곳의 `auth.uid()`를 전부 치환하는 안이
> 있었으나, 손으로 고치다 한 곳만 빠뜨려도 권한 구멍이 된다. 함수 하나를
> 갈아끼우면 **검증된 권한 규칙이 그대로 살아남는다.**
>
> 당초 로드맵은 "RLS를 앱 계층으로 이전"이었는데 **뒤집었다.** RLS는 Supabase
> 기능이 아니라 Postgres 기능이라 Supabase를 빼도 그대로 쓴다. 앱으로 옮기면
> 한 군데만 빠뜨려도 데이터가 새는데, 이전 비용이 0에 가까운 길이 있었다.

역할도 DB로 재현했다: `nodi_app`(RLS 적용) / `nodi_worker`(BYPASSRLS).
비밀번호 해시가 든 `public.users`는 `nodi_app`에 **GRANT 자체를 주지 않는다** —
정책보다 앞선 단계에서 막힌다.

### 인터페이스를 유지해 호출부를 지켰다

서비스 코드 수백 곳이 `select/insert/update/upsert/delete/rpc/count`에 의존하고
있었다. 시그니처를 그대로 두고 구현만 바꿨다. 그래서 PostgREST 문법
(`{"id": "eq.x", "order": "created_at.desc"}`)을 SQL로 번역하는 계층이 필요했고,
그게 `db/query.py`다.

### 이때 터진 것

**채팅이 전면 차단**(`8b0179c`). PostgREST는 JSON을 돌려줘 uuid·timestamptz가
전부 **문자열**이었는데 asyncpg는 `UUID`·`datetime` 객체를 돌려준다. 파이썬에서
`UUID(...) == "..."`는 **항상 거짓**이라, `chat.py`의 소유자 비교가 늘 참이 되어
모든 질문이 403으로 거부됐다. 호출부 수십 곳 대신 **경계 한 곳**(`_jsonable`)에서
옛 계약(문자열)으로 되돌려 고쳤다.

**가입 시 이름·역할 유실**(`4045844`) — 메타데이터 이중 인코딩.

## 2. 정리·최적화 (D105)

Supabase를 걷어낸 뒤 남은 죽은 코드를 걷어냈다.

- **좌표 영속 경로 제거** — 카드 배치가 프론트 d3-force로 넘어가면서 서버가
  계산·저장하던 경로가 통째로 죽어 있었다. 프론트·백엔드·DB에서 함께 제거.
- **`canvas_cards` 벡터 컬렉션 제거** — 카드 제목·좌표를 벡터로 들고 있었으나
  쓰는 쪽이 사라졌다. 미참조 헬퍼 5종도 함께.
- **`embedding_worker.py` 1,133줄 → `worker/` 패키지 분해**
  (jobs·split·batch·figures·common·runner).
- **백엔드 라우터를 `/api` 접두사 아래로** — `/health`만 밖(인프라 liveness 계약).
- **프론트엔드 테스트 도입 0개 → 50개**(vitest). tsc·build만으로는 배치 좌표
  오류나 파서의 제어 토큰 누출을 잡을 수 없다 — **둘 다 실제로 발생했다.**
- **`jobs.parent_job_id` 인덱스** — CASCADE 삭제 실측 279.5ms → 13.7ms(20배).
- **4xx 재시도 중단** — 되지 않을 요청을 반복하고 있었다.

임베딩·문서 파싱이 이미 Upstage라 **외부 벤더가 하나로 줄었다.**

### EXAONE 도판 이미지 인식은 임시로 꺼 뒀다

EXAONE이 하던 일은 둘이었다 — 대화 생성과 **교과서 도판 캡션 비전 판정**.
대화 생성은 위처럼 Upstage로 옮겼고, **도판 판정은 이번에 옮기지 않고 껐다**
(사용자 결정: "도판 검사 기능은 아직 구현하지 말고").

- **코드는 지우지 않았다.** `services/figure_judge.py`와 워커의 호출 경로가
  그대로 있다. `JUDGE_API_KEY` · `JUDGE_BASE_URL`을 **비워 둔 것**이 전부다.
- 워커가 `figure_judge.is_configured()`로 먼저 확인하고, 미설정이면 판정이
  필요한 도판만 건너뛴다(`status='failed'`). **캡션을 지어내지 않는다.**
- 파서가 `caption`/`footnote`로 라벨한 도판은 판정 없이 그대로 처리된다(D103의
  2단 경로 중 1단). 즉 **교과서 업로드는 막히지 않고, 라벨 없는 도판만
  처리되지 않는다.**
- `/health/config`의 `judge.configured: false`와 운영 콘솔 개요의 환경 패널에서
  이 상태가 그대로 보인다.

되살릴 때는 두 값을 채우면 된다. 다만 요청 파라미터가 EXAONE 4.5 실측값
(`chat_template_kwargs.enable_thinking` 등)이라 다른 모델을 꽂으면 무시되거나
400이 날 수 있어 검증이 필요하다.

> ⚠️ **살아있지 않은 주소를 넣지 말 것.** 설정만 채워져 있으면 게이트는 통과하는데
> 실제 호출이 전부 실패해 도판이 조용히 사라진다. 쓸 게 없으면 비워 두는 편이
> 낫다.

## 6. ReAct 스킬 계층 (D109 · D111)

**가장 큰 동작 변화.** 예전에는 인사 한 마디에도 질의 임베딩 + Qdrant 검색 +
최대 15만 자 컨텍스트 주입이 나갔다. 이제 모델이 **필요할 때만** 도구를 부른다.

### 2단계로 나눈 이유

한 번의 호출로 "도구도 고르고 개념 카드도 쓰게" 하면 두 지시가 충돌한다.
형식을 지키느라 도구를 안 부르거나, 도구를 부르느라 형식을 깬다. 그래서 **시점**
으로 역할을 나눴다:

- **판단 단계** — 개념 카드 형식을 주지 않는다. 도구 설명만. 비스트리밍이고
  이 단계의 텍스트는 **버린다**(모델이 추론 과정을 content에 흘리는 일이 실제로
  있는데, 그게 화면으로 새지 않는다).
- **생성 단계** — 기존 개념 카드 프롬프트 그대로. `tools`를 **주지 않는다**.

### 3층 도구 선택

1. **카탈로그가 좁힌다**(서버) — `(공간, 역할, 세션 상태)`로 쓸 수 없는 도구를
   애초에 안 보여준다. 개인 세션에 학급 도구를 노출하면 모델이 부르고 빈 결과를
   받아 "자료를 찾을 수 없다"는 엉뚱한 답을 한다.
2. **모델이 고른다** — 인사 턴에는 아무것도 안 고른다(실측 확인).
3. **스킬 안에서 RLS** — 모든 DB 접근이 호출자 스코프 클라이언트를 거친다.

스킬 9종: `think` · `search_class_material` · `search_textbook_figure` ·
`list_session_concepts` · `get_concept` · `list_session_files` ·
`read_session_file` · `list_class_materials` · `summarize_class_questions`.
스킬 하나가 파일 하나다.

### D111 — `/retrieve` 제거

**프론트가** SSE 전에 `/retrieve`를 따로 불러 도판을 받아 오던 구조를 없앴다.
문제가 둘이었다: ① 무조건 호출이라 인사에도 검색이 나갔다, ② 검색 오케스트레이션이
클라이언트에 남아 ReAct 스킬과 **중복**됐다(학급 세션에서 두 번 검색됐다).

## 7. 데이터 계층 결함 (D110 · D112)

D104의 여파로 **쓰기 경로**에 남아 있던 타입 불일치를 잡았다.

- **파일 인제스트가 통째로 죽어 있었다**(D110). `rows[0]`을 dict에 적용, ISO
  문자열을 timestamptz에, 문자열을 int 컬럼에. **테스트 대역이 잘못된 계약을
  인코딩하고 있어서**(insert가 list를 반환) 초록으로 통과하고 있었다.
- 타입 추측을 없앴다 — 서버가 선언한 파라미터 타입을 읽어 그대로 변환한다.
  타입 조회는 SQL별 1회 캐시(실측: 매번 `prepare()`는 일반 `fetch()` 대비 3.09배 느림).
- **`_encode`의 ISO 추측 제거**(D112) — 형태만 보고 datetime으로 승격하다
  **text 컬럼에 저장할 값까지 바꿨다.** 파일명이 `2026-07-28T10:00:00.txt`면
  업로드가 죽었다.
- **도구 결과가 생성 단계에 닿지 않던 문제** — 근거 블록이 RAG·도판만 렌더해
  나머지 스킬 결과가 버려졌다. `summarize_class_questions`가 실제 질문 16건을
  돌려줬는데 답변은 "시험 범위 질문이 많다"는 **창작**이었다.
- 중복 도구 호출 생략, 응답 절단(`finish_reason=length`) 경고, 카탈로그↔레지스트리
  부팅 대조 가드.

## 8. 운영 콘솔 (D113)

관리자 페이지 **3탭 → 9탭**. "서비스가 무슨 일을 하는지, 왜 그렇게 됐는지"를
화면 하나에서 보고 거기서 바로 조정한다.

개요 · AI 흐름 · 대화 · 턴 로그 · 스킬 · 문서 · RAG 테스트 · 설정 · 권한.

### 관측 데이터를 새로 만들었다

`ai_logs`에 컬럼 4개 추가:

| 컬럼 | 내용 |
|---|---|
| `tokens` jsonb | 공급자 **실측** usage(단계별 내역·캐시 히트 포함). 측정값이 없으면 `{}` |
| `route` text | `react` \| `legacy` |
| `model` text | 사용 모델 |
| `duration_ms` int | 턴 전체 소요 |

`skill_calls`에는 스킬마다 인자·결과·성공 여부·소요시간이 들어간다.

**어림을 실측 자리에 앉히지 않았다.** `token_estimate`(글자수÷4)는 한국어에서
크게 빗나간다 — 같은 턴 **어림 604 vs 실측 2,731**(4.5배). 둘을 나란히 두고,
실측이 없으면 화면에 "실측 없음"이라 쓴다.

> 스트리밍은 `stream_options.include_usage=true`를 붙여야 usage가 온다(실측 확인).
> 덤으로 `cached_tokens`가 와서 프리픽스 캐시가 먹는지 볼 수 있다.

### 그 밖의 설계 판단

- **흐름 그림을 서버가 만든다** — 스킬 이름·활성 경로를 프론트에 적어 두면
  코드가 바뀔 때 그림만 옛말이 된다.
- **RAG 테스트는 게이트를 필터가 아니라 표시로 쓴다** — 채팅과 같은 함수를
  태우되 잘린 청크를 거리와 함께 보여준다. 실측: "광합성이 무엇인가" 0.483 통과 /
  "오늘 날씨 어때" 0.858 차단(표시됨) / 게이트 0.9로 올리면 통과.
- **튜너블 스펙의 소유자를 서버로** — 기본값이 `config.py`에 있으니 라벨·범위도
  옆에 둔다. `app_settings`에 행이 없는 키도 내보내고 `missing_row`로 드러낸다.
- **턴별 흐름 뷰** — AI 흐름과 **같은 그림** 위에 이 턴이 어디를 탔는지 덧칠한다.
  스킬을 안 쓴 턴도 전체 흐름이 나오고, 어느 칸을 왜 건너뛰었는지 표시된다.
  빈 화면은 정상인지 고장인지 구분해 주지 못한다.

## 9. 데이터 백업 · 복원 · 초기화 (D114)

10번째 탭. **백업 없는 초기화는 기능이 아니라 사고다** — 셋을 한 화면에 뒀다.

스냅샷은 JSON 한 파일(`backend/.storage/backups/`). 스코프는
`conversations` · `documents` · `people` · `settings`.

**의도적으로 막은 것:**

- `documents`는 **복원 대상이 아니다** — 스냅샷에 원본 바이트도 벡터도 없어
  행만 되살리면 껍데기가 남는다.
- `people`(계정·학급)은 **초기화 대상이 아니다** — 계정을 지우면 그 사람의
  모든 것이 CASCADE로 사라진다.

**안전장치:** 확인 문구(`초기화합니다`) 정확 입력, 기본값이 "지우기 전 자동
백업", **백업 실패 시 삭제하지 않음**, 백업 이름의 디렉터리 탈출 2중 차단.

**복원은 덮어쓰지 않는다**(설정만 예외). 문서 삭제는 SQL이 아니라 파일마다
기존 삭제 경로를 타 **Storage 원본·도판 크롭·Qdrant 벡터**를 함께 정리한다.

## 10. DB 변경 총괄

### 스키마 관리 방식이 두 번 바뀌었다

1. **D104** — 마이그레이션 0001~0042를 `pg_dump`로 스쿼시해 **파일 5개**로.
   42개 중 절반이 생성 후 삭제된 것(art_assets·tags·ai_sessions·pgvector 등)이라
   이력 가치보다 죽은 코드 비용이 컸다. 이후 변경은 `01_schema.sql` 수정 +
   `down -v` 재적용 — 그런데 **이건 데이터를 지운다.**
2. **D113** — 개발 DB에 계정·학급·자료가 쌓인 뒤로는 `down -v`를 쓸 수 없어
   **`db/migrations/` 폴더를 신설**했다. 성격이 다르다:

| | `db/*.sql` (00~04) | `db/migrations/*.sql` |
|---|---|---|
| 적용 | 빈 볼륨일 때 **자동 1회** | **손으로** 실행 |
| 대상 | 새 환경 | 이미 데이터가 든 DB |
| 성질 | 현재 상태 스냅샷 | 멱등(여러 번 안전) |

Postgres 엔트리포인트는 하위 디렉터리를 건너뛰므로 `db/`를 통째로 마운트해도
자동 실행되지 않는다. **같은 변경을 두 곳에 넣는다** — `01_schema.sql`(새 환경)과
`migrations/`(기존 DB). 양쪽이 같은 결과를 내는지 클린 클론으로 확인했다.

### 수치 변화

| | D104 직후 | 현재 |
|---|---|---|
| 테이블 | 11 (+ `public.users`) | 동일 |
| RLS 정책 | 32 | **38** |
| DB 함수 | 19 | **26** |
| 튜너블(`app_settings`) | 11 | **13** |

**정책 +6** — 읽기 전용 admin: `nodes` · `files` · `file_chunks` ·
`textbook_figures` · `classes` · `class_members`.
`can_access_session()`에 `is_admin()`을 섞지 **않았다** — 그 함수의 뜻은 "세션
소유자 또는 담임"이고, 거기 admin을 넣으면 그 함수를 쓰는 다른 곳까지 조용히
넓어진다.

**함수 +7** — `admin_overview` · `admin_conversations` · `admin_documents` ·
`admin_skill_usage` · `admin_purge_conversations` · `admin_restore_conversations` ·
`admin_restore_settings`. 전부 SECURITY DEFINER이며 안에서 `is_admin()`을 확인한다.
`delete_file_cascade`는 관리자도 호출 가능하게 넓혔다.

**튜너블 +2** — `react_enabled` · `react_max_steps`.

### 적용 방법 (기존 DB)

```bash
docker exec -i nodi-postgres-1 psql -U postgres -d nodi \
  < db/migrations/2026-07-28-d113-admin-observability.sql
# 이어서 -d113-admin-console-rpc.sql, -d114-backup-purge.sql
```

전부 멱등. 새로 시작하는 환경은 `01_schema.sql`에 이미 반영돼 있어 필요 없다.

## 11. 이 기간에 잡은 결함

| 결함 | 어떻게 드러났나 |
|---|---|
| **채팅 전면 차단**(D104) | UUID vs str 비교가 항상 참 → 모든 질문 403 |
| **파일 인제스트가 통째로 죽어 있었다**(D110) | 테스트 대역이 잘못된 계약을 인코딩해 초록으로 통과 중이었다 |
| **`_encode`가 text 컬럼을 망가뜨림**(D112) | 파일명이 ISO처럼 생기면 업로드가 DataError |
| **도구 결과가 생성 단계에 닿지 않음**(D112) | 스킬이 질문 16건을 돌려줬는데 답변은 창작이었다 |
| **관리자가 학급을 하나도 못 봄**(D113) | RAG 테스트 범위 목록이 0건 |
| **기록은 하는데 조회하지 않던 컬럼**(D113) | 컬럼을 넣고 select를 안 늘려 DB엔 있는데 화면엔 없었다 |
| **토글 손잡이가 트랙 밖으로 14px**(D113) | `left` 미지정 → button 기본 `text-align:center`가 정적 위치를 중앙으로 |
| **백업이 통째로 502**(D114) | `class_members.joined_at`을 짐작해서 적었는데 실제는 `created_at` |
| 종료 토큰 변형(`/end` 등) 본문 노출 | 파서가 변형을 못 걸렀다 |
| 캔버스 매 프레임 리렌더 사슬 | 카메라 효과 deps에 `positions` |
| 채팅 버블에 `==강조==` 마커 노출 | CHAT 줄이 마크업 스캐너를 안 거쳤다 |

**되풀이를 막는 테스트**를 붙였다. 특히 DB 없이 도는 둘:
`TurnLog.to_row()`가 쓰는 컬럼이 전부 조회 select에 있는지 대조 /
백업이 읽는 모든 컬럼이 `db/01_schema.sql`에 실재하는지 대조.

### 오탐이었던 것

- **RLS 유출 의심** — "교사에게 남의 세션 11개가 보인다"가 나왔으나 전부 담임
  학급 세션(정책상 허용)이었다. 학생 개인 세션이 교사에게 보인 것은 0건.
- **캔버스 `ReferenceError`** — 소스에 없는 식별자였다. `npm run build`가 dev
  서버의 `.next/`를 덮어써 생긴 잔재. dev 서버 재시작으로 사라졌다.
  → dev 서버를 띄운 채 빌드하지 말 것.

## 12. 개발 DB에 실제로 한 작업

로컬 개발 DB(`nodi`)에 아래를 실행했다. "왜 대화가 없어졌지?"가 나오지 않도록 남긴다.

1. **마이그레이션 3개 적용** — 정책 32 → 38, 함수 19 → 26.
2. **대화 기록 전체 초기화**(사용자 지시) — 콘솔의 초기화 기능으로 실행.

   | | 이전 | 이후 |
   |---|---|---|
   | 세션 | 29 | **0** |
   | 노드 | 44 | **0** |
   | 턴 로그 | 59 | **0** |
   | 문서 / 학급 / 계정 | 6 / 4 / 6 | 6 / 4 / 6 (무영향) |

   사전 자동 백업 **`nodi-20260728-134909.json`**(299KB)에 지워진 것이 전부
   들어 있고, 콘솔 데이터 탭에서 복원할 수 있다.

3. **검증용 계정 3개 생성** — `probe-admin@` / `probe-teacher@` /
   `probe-student@nodi.local`. 콘솔 확인에 admin 계정이 필요했다. 필요 없으면
   지워도 된다. 비밀번호는 **저장소에 적지 않는다**.

4. **임시 DB 생성·삭제** — `nodi_scratch`(스키마 검증), `nodi_fresh`(새 클론
   E2E). 둘 다 확인 후 삭제했고 `nodi`는 건드리지 않았다.

## 14. 알려진 사항

- **`JWT_SECRET`이 기본값**이다. 이 값이면 누구나 토큰을 위조할 수 있다.
  (`/health/config`의 `secret_is_default`로 확인)
- `npm audit` **high 6건** — 전부 빌드·개발 시점 의존성이라 실행을 막지 않는다.
- **EXAONE 도판 이미지 인식이 꺼져 있다**(§5) — 임시 조치이며 코드는 그대로다.
  `JUDGE_API_KEY`·`JUDGE_BASE_URL`을 채우면 되살아난다. 지금은 파서가 캡션으로
  라벨하지 않은 도판만 처리되지 않는다(업로드 자체는 정상).
- **문서 2건이 `uploaded`에서 멈춰 있다** — 백엔드 재시작 시 워커가 같이 죽어
  생겼다. 콘솔 문서 탭이 "진행률 불일치"로 드러낸다. 재시도 API는 있으나 콘솔에
  연결하지 않았다(콘솔에서 쓰기 동작을 어디까지 허용할지 미정).
- **`backend/README.md`는 Stage 0 시절 문서**라 Admin 절 외에는 낡았다.
