## 2. 운영 콘솔 (D113)

`/admin`, 관리자 전용. 탭 순서는 "무슨 일이 일어나는가 → 왜 그렇게 되는가 →
무엇을 바꾸는가".

- **개요** — 사용자·세션·문서·청크·잡·턴 카운터, 실측 토큰 합계와 캐시 히트율,
  지연 p50/p95, **환경**(기동 시 결정된 값 — 모델·DSN 호스트·Qdrant·저장소).
- **AI 흐름** — 채팅 한 턴의 파이프라인 그래프. 단계마다 코드 위치·걸린 튜너블·
  설계 이유. 꺼진 경로(레거시)도 흐리게 함께 그린다.
- **대화** — 모든 사용자의 대화를 **세션 단위**로. 열면 말풍선 순서로 이어지고,
  턴마다 "이 답이 나온 과정"을 접어 둔다.
- **턴 로그** — 턴 단위 모니터 + 상세. 상세 맨 위 **"이 턴의 흐름"**이 AI 흐름과
  같은 그림 위에 이 턴이 어디를 탔는지 보여준다(스킬을 안 쓴 턴도 전체 흐름이
  나오고, 어느 칸을 왜 건너뛰었는지 표시된다).
- **스킬** — 등록 스킬 9종, 노출 조합, 인자 스키마, 실사용 통계.
- **문서** — 인제스트 현황(청크 행 수·임베딩 성공·도판), 상세에서 청크 원문과
  잡 이력.
- **RAG 테스트** — 실제 검색 경로를 그대로 태우되 게이트에 걸린 청크도 보여준다.
- **설정** — 튜너블 전체(현재값·기본값·변경 여부·반영 시점), 저장·기본값 복귀.
- **데이터** — 백업·복원·초기화(§3).
- **권한** — 기존 역할 관리.

### 설계상 지킨 것

**어림을 실측 자리에 앉히지 않는다.** `token_estimate`는 `글자수/4` 휴리스틱인데
한국어에서 크게 빗나간다 — 같은 턴 실측 결과 **어림 604 vs 실측 2,731**(4.5배).
`ai_logs.tokens`에는 공급자 usage만 담고, 실측이 없는 턴은 화면에 "실측 없음"이라
쓴다.

> 스트리밍은 `stream_options.include_usage=true`를 붙여야 usage가 온다(실측 확인,
> 400 아님). 덤으로 `cached_tokens`가 와서 프리픽스 캐시가 먹는지 볼 수 있다.

**게이트는 필터가 아니라 표시.** RAG 테스트는 채팅과 **같은 함수**(`rag.search`)를
쓴다 — 테스트 전용 사본을 만들면 사본만 맞고 실제 경로는 다른 상황이 된다.

**흐름 그림은 서버가 만든다.** 스킬 이름·활성 경로를 프론트에 적어 두면 코드가
바뀔 때 그림만 옛말이 된다. `services/admin_console.flow_spec()`이 레지스트리와
설정에서 끌어온다.

**튜너블 스펙의 소유자는 서버.** 기본값이 `config.py`에 있으니 라벨·범위도 옆에
둔다. `app_settings`에 **행이 없는 키도 함께 내보내고** `missing_row`로 드러낸다 —
행이 없으면 조정 자체가 불가능한데 조용히 안 보이면 알 수 없다.

**권한은 계속 DB가 강제한다.** 콘솔이 넓게 본다고 service_role을 쓰지 않는다.
관리자 본인 JWT로 돌고, 읽기 전용 admin 정책과 `is_admin()`을 확인하는 RPC로
넓힌다.

## 3. 백업 · 복원 · 초기화 (D114)

셋을 한 화면에 둔다 — **백업 없는 초기화는 기능이 아니라 사고다.**

스냅샷은 JSON 한 파일이고 `backend/.storage/backups/`에 쌓인다. 스코프는
`conversations` · `documents` · `people` · `settings`.

**의도적으로 막아 둔 것:**

- **`documents`는 복원 대상이 아니다.** 스냅샷에 원본 파일 바이트도 Qdrant
  벡터도 없어서, 행만 되살리면 본문도 검색도 없는 껍데기가 남는다.
- **`people`(계정·학급)은 초기화 대상이 아니다.** 계정을 지우면 그 사람의 모든
  것이 CASCADE로 사라지고 되돌릴 수 없다.

**안전장치:** 확인 문구(`초기화합니다`)를 정확히 입력해야 하고, 기본값이 "지우기
전 자동 백업"이며 **백업이 실패하면 지우지 않는다.** 백업 이름은 화이트리스트
정규식 + 경계 재확인 2중으로 디렉터리 탈출을 막는다.

**복원은 덮어쓰지 않는다.** 같은 id가 이미 있으면 건너뛴다(설정만 예외). 문서
삭제는 SQL이 아니라 파일마다 `files.delete_file`을 부른다 — 그래야 Storage
원본·도판 크롭·**Qdrant 벡터**가 함께 정리된다.

> ⚠️ **스냅샷에는 학생 대화 원문이 그대로 들어 있다.** 서버 안에만 두고, 내려받은
> 파일을 외부로 옮기면 그 내용도 함께 나간다.

## 4. DB 변경

### 4-1. `db/migrations/` 폴더 신설 — 새 규약

지금까지 스키마 변경은 `01_schema.sql` 수정 + `down -v` 재적용뿐이었고, 그건
**데이터를 지운다.** 개발 DB에 계정·학급·자료가 쌓인 뒤로는 쓸 수 없는 방법이다.

그래서 `db/migrations/`를 만들었다. 성격이 다르다:

| | `db/*.sql` (00~04) | `db/migrations/*.sql` |
|---|---|---|
| 적용 | 빈 볼륨일 때 **자동 1회** | **손으로** 실행 |
| 대상 | 새 환경 | 이미 데이터가 든 DB |
| 성질 | 현재 상태 스냅샷 | 멱등(여러 번 안전) |

Postgres 엔트리포인트는 하위 디렉터리를 건너뛰므로 `db/`를 통째로 마운트해도
자동 실행되지 않는다. **두 곳에 같은 변경을 넣는다** — `01_schema.sql`(새 환경용)
과 `migrations/`(기존 DB용). 이번 변경도 그렇게 했고, 새 클론 + 빈 DB로 양쪽이
같은 결과(정책 38)를 내는지 확인했다.

### 4-2. `ai_logs` 관측 컬럼 4개

| 컬럼 | 내용 |
|---|---|
| `tokens` jsonb | 공급자 **실측** usage. `{prompt, completion, total, cached, calls:[{stage,…}]}`. 측정된 호출이 없으면 `{}` |
| `route` text | `react` \| `legacy` — 어느 경로로 돈 턴인지 |
| `model` text | 사용한 모델 |
| `duration_ms` int | 턴 전체 소요 |

`skill_calls`는 칸은 그대로지만 내용이 풍부해졌다 — 스킬마다 인자·결과·성공
여부·소요시간(결과는 4,000자 상한, 자르면 `_truncated`로 알린다).

### 4-3. RLS 정책 +6 (32 → 38)

읽기 전용 admin 정책: `nodes` · `files` · `file_chunks` · `textbook_figures` ·
`classes` · `class_members`.

`can_access_session()`에 `is_admin()`을 섞지 **않았다** — 그 함수의 뜻은 "세션
소유자 또는 담임"이고, 거기 admin을 넣으면 그 함수를 쓰는 다른 곳까지 조용히
넓어진다. 별도 정책으로 뒀다.

### 4-4. DB 함수 +7 (19 → 26)

`admin_overview` · `admin_conversations` · `admin_documents` · `admin_skill_usage` ·
`admin_purge_conversations` · `admin_restore_conversations` · `admin_restore_settings`.
전부 SECURITY DEFINER이며 함수 안에서 `is_admin()`을 확인한다.
`delete_file_cascade`는 관리자도 호출할 수 있게 넓혔다(콘솔의 문서 초기화가 이
함수를 재사용해야 Qdrant 정리 경로가 하나로 유지된다).

## 5. 개발 DB에 실제로 한 작업 (운영 기록)

로컬 개발 DB(`nodi-postgres-1` / `nodi`)에 이번 세션에서 아래를 실행했다. 팀
공유 DB가 아니라 오너 로컬이지만, "왜 대화가 없어졌지?"가 나오지 않도록 남긴다.

1. **마이그레이션 3개 적용** — §8의 그 명령 그대로. 정책 32 → 38, 함수 19 → 26.
2. **대화 기록 전체 초기화** (사용자 지시) — 콘솔의 초기화 기능으로 실행했다.

   | | 이전 | 이후 |
   |---|---|---|
   | 세션 | 29 | **0** |
   | 노드 | 44 | **0** |
   | 턴 로그(ai_logs) | 59 | **0** |
   | 문서 / 학급 / 계정 | 6 / 4 / 6 | 6 / 4 / 6 (무영향) |

   지우기 직전 자동 백업 **`nodi-20260728-134909.json`**(299KB)에 지워진 것이
   전부 들어 있다. 콘솔 데이터 탭에서 복원할 수 있다.

3. **검증용 계정 3개 생성** — `probe-admin@` / `probe-teacher@` /
   `probe-student@nodi.local`. 콘솔을 실제로 확인하려면 admin 계정이 필요한데
   기존 계정 비밀번호를 몰라서 만들었다. 필요 없으면 지워도 된다.
   비밀번호는 **저장소에 적지 않는다** — 오너에게 문의.
   (probe 계정이 만든 "관측 점검 2반" 학급과 업로드 자료도 함께 남아 있다.)
4. **임시 DB 생성·삭제** — 스키마 검증용 `nodi_scratch`, 새 클론 E2E용
   `nodi_fresh`. 둘 다 확인 후 삭제했고 `nodi`는 건드리지 않았다.

- 백업이 읽는 모든 컬럼이 `db/01_schema.sql`에 실재하는지 대조

## 7. 오탐이었던 것 (기록)

실브라우저 점검 중 캔버스에서 `ReferenceError: sig is not defined` 등이 보였다.
소스에 `sig`는 존재하지도 않고 `emitBody`는 호이스팅된 함수 선언이라 "not
defined"가 나올 수 없다 — **`npm run build`가 dev 서버의 `.next/`를 덮어써서**
생긴 잔재였다. dev 서버를 재시작하니 사라졌다.

> **dev 서버를 띄운 채 `npm run build`를 돌리지 말 것.** 빌드했으면 dev 서버를
> 재시작한다.

또 하나: 관리자 RLS 점검에서 "교사에게 남의 세션 11개가 보인다"가 나왔는데,
확인해 보니 전부 담임 학급 세션이었다(정책상 허용). 학생 개인 세션이 교사에게
보인 것은 0건. 유출이 아니었다.

## 8. 팀원이 해야 할 일

### 새로 시작하는 경우 — 할 일 없음

`db/01_schema.sql`에 전부 반영돼 있다. `docker compose up -d` 하면 끝이다.
`db/migrations/`는 **자동 적용되지 않으며 볼 필요도 없다.**

### 이미 데이터가 든 DB를 쓰는 경우 — 마이그레이션 3개를 손으로 적용

적용하지 않으면 콘솔이 500이나 빈 화면으로 뜬다(컬럼·함수·정책이 없다).

```bash
cd Nodi
docker exec -i nodi-postgres-1 psql -U postgres -d nodi \
  < db/migrations/2026-07-28-d113-admin-observability.sql
docker exec -i nodi-postgres-1 psql -U postgres -d nodi \
  < db/migrations/2026-07-28-d113-admin-console-rpc.sql
docker exec -i nodi-postgres-1 psql -U postgres -d nodi \
  < db/migrations/2026-07-28-d114-backup-purge.sql
```

전부 멱등이라 여러 번 돌려도 안전하다(실제로 재적용해 확인했다). 적용 후:

```sql
select count(*) from pg_policies where schemaname='public';   -- 38
```

### 관리자 계정

콘솔은 `admin` 역할만 들어간다. 가입 폼으로는 얻을 수 없다:

```bash
cd backend
```

## 10. 알려진 사항

- **`JWT_SECRET`이 기본값**이다. 이 값이면 누구나 토큰을 위조할 수 있다.
  `.env`를 공유하더라도 각자 다른 값으로 바꾸는 것을 권한다
  (`/health/config`의 `secret_is_default`로 확인).
- `npm audit` **high 6건** — 전부 빌드·개발 시점 의존성(`postcss`·`next`·
  `sharp`·`js-yaml`·`brace-expansion`)이라 실행을 막지 않는다.
- **도판 비전 판정 미설정** — 설계상 정상. 파서가 캡션으로 라벨하지 않은 도판만
  처리되지 않는다.
- **문서 2건이 `uploaded`에서 멈춰 있다**(오너 로컬). 백엔드 재시작 시 워커가
  같이 죽어 생긴 것으로, 콘솔 문서 탭이 "진행률 불일치"로 드러낸다. 재시도 API는
  있으나 콘솔에 연결하지 않았다 — 콘솔에서 쓰기 동작을 어디까지 허용할지 정해진
  바가 없다.
